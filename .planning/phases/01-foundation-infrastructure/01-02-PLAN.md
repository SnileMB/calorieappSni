<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → Postgres via PostgREST | Any holder of a valid user JWT can issue arbitrary PostgREST queries; RLS is the only thing scoping them to their own rows |
| anon key holder → Postgres | The anon key is public; unauthenticated requests must see nothing |
| local shell → Supabase remote project | `SUPABASE_ACCESS_TOKEN` / DB password grant full project control and must never enter a committed file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-RLS | Information Disclosure | `public.profiles` | mitigate | RLS enabled in the same migration as `create table` (no unprotected window); all four CRUD policies scoped `(select auth.uid()) = id`; verified by pgTAP test AND a live two-account PostgREST negative check in Task 3 |
| T-01-05 | Elevation of Privilege | RLS policy role targeting | mitigate | Every policy declared `to authenticated`; omitting it would extend the policy to the `anon` role. Asserted by grep count in Task 2 acceptance criteria and by the anon-key-returns-empty-array check in Task 3 |
| T-01-06 | Tampering | Cross-user writes | mitigate | Update policy carries both `using` and `with check`; delete policy carries `using`. Task 3 asserts A's `PATCH` of B's row affects 0 rows |
| T-01-07 | Information Disclosure | Project credentials | mitigate | Access token and DB password stay as shell env vars only; `.env` holds only the public URL + anon key and is gitignored; acceptance criteria grep `.env` for forbidden secret names |
| T-01-08 | Repudiation / Tampering | Schema drift | mitigate | Schema applied exclusively via `supabase db push` from a committed migration file — no ad hoc dashboard SQL, so the repo is the auditable source of truth |
| T-01-SC | Tampering | Supabase CLI install | mitigate | CLI is `[ASSUMED]` provenance per RESEARCH.md — verify it resolves to the official `supabase/cli` GitHub release or `npx supabase` before installing |
</threat_model>
