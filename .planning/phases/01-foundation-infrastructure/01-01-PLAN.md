<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build output → public internet | Everything in `dist/` (including all `VITE_*` env values) is world-readable; no secret may cross this boundary |
| browser client → Supabase PostgREST/Auth | Untrusted client input crosses into the backend; the client is never the security boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `src/lib/env.ts`, build output | mitigate | Only `VITE_SUPABASE_URL` + anon key are exposed; Task 3 test fails the build if `service_role`/`SUPABASE_SERVICE` appears anywhere under `src/`. Anon key is public by design (RESEARCH.md Security Domain) — RLS in plan 01-02 is the real boundary |
| T-01-02 | Elevation of Privilege | Supabase client construction | mitigate | Single `createClient` call enforced by automated test, so no second client can be constructed with elevated credentials or with `persistSession` disabled |
| T-01-03 | Spoofing | Auth mechanism choice | mitigate | Automated test asserts `signInAnonymously` never appears in `src/` (SYNC-02 requires real email/password identity) |
| T-01-04 | Information Disclosure | `.env` committed to git | mitigate | `.env`/`.env.local` added to `.gitignore` in Task 1; only `.env.example` with empty values is committed |
| T-01-SC | Tampering | npm install | mitigate | All five packages cleared `[OK]` by the Package Legitimacy Audit in RESEARCH.md; any package outside that table must be flagged to the user, not installed |
</threat_model>
