# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 1's user-visible surface is intentionally thin — no app features exist yet (diary/logging start Phase 2). This contract covers exactly three UI elements: the sign-up form, the sign-in form, and the PWA install experience (native prompt on Chrome/Android, custom instructional banner on iOS Safari). No data views, no empty states, no destructive actions exist in this phase's actual scope — those sections below are marked "not applicable" rather than invented.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no `components.json` found; repo is greenfield (no `package.json` yet). shadcn requires an interactive step (visit ui.shadcn.com/create, paste a preset string) that has no user available to complete in this research session. Given Phase 1's entire UI surface is 2 forms + 1 banner, scaffolding a full component library now is disproportionate — **recommend running the shadcn init gate at the start of Phase 2 planning**, when richer UI surfaces (capture, review, diary) actually need a component system. |
| Preset | not applicable this phase |
| Component library | none — plain React function components + plain CSS (CSS custom properties for tokens below) |
| Icon library | none required this phase (no icons needed for auth forms; install banner may use a single inline SVG share-icon glyph, hand-authored, no library dependency) |
| Font | system font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — zero network font load keeps the offline app-shell (D-06) genuinely instant with no FOIT/FOUT risk, and matches native iOS Safari install-to-Home-Screen conventions |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g. input icon to label) |
| sm | 8px | Compact element spacing (label-to-input gap) |
| md | 16px | Default element spacing (between form fields) |
| lg | 24px | Section padding (form container padding) |
| xl | 32px | Layout gaps (space above/below the auth form card) |
| 2xl | 48px | Major section breaks (vertical centering offset on auth screen) |
| 3xl | 64px | Page-level spacing (top margin on mobile viewport) |

Exceptions: touch targets (buttons, inputs, install-banner dismiss control) must be minimum 44px tall regardless of the scale above, per iOS Human Interface Guidelines tap-target minimum — this applies to every interactive element in this phase (Sign Up button, Sign In button, form inputs, install banner CTA/dismiss).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

Usage: Display = app name on auth screen ("BOBLUR"). Heading = form titles ("Sign Up" / "Log In"). Body = form field values, button labels, install-banner instructional copy. Label = input field labels, helper/error text under fields.

Exactly 2 weights declared (400, 600) — do not introduce a third weight (e.g. no 500/medium) anywhere in this phase's UI.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form card background |
| Secondary (30%) | `#F1F5F9` | Input field backgrounds, install-banner surface, disabled states |
| Accent (10%) | `#2563EB` | Primary CTA buttons (Sign Up, Log In, Install), input focus ring/border, links (e.g. "Already have an account? Log in") |
| Destructive | `#DC2626` | Form validation error text/border only (e.g. invalid credentials, weak password) — no destructive *actions* exist in Phase 1 scope (no delete/logout-everywhere/data-wipe flows), so this color's only job here is signaling auth errors, not confirming a destructive action |

Accent reserved for: the Sign Up button, the Log In button, the Install/Add-to-Home-Screen CTA, input focus rings, and the single "switch between sign up / sign in" text link. Never apply accent to body text, card backgrounds, or non-interactive decoration.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (sign up) | "Create Account" |
| Primary CTA (sign in) | "Log In" |
| Primary CTA (install, Chrome/Android — native `beforeinstallprompt`) | "Install App" |
| Primary CTA (install, iOS Safari — instructional banner, no native prompt exists) | Heading: "Install BOBLUR" · Body: "Tap the Share icon, then \"Add to Home Screen\"" — per RESEARCH.md D-06/Pitfall 1, this is manual instructional copy, not a clickable install trigger, since `beforeinstallprompt` never fires on iOS |
| Empty state | not applicable — Phase 1 has no data views (diary/lists start Phase 2) |
| Error state (auth) | "That email or password didn't work. Check your details and try again." (invalid credentials) · "Couldn't reach the server — check your connection and try again." (network failure) — problem stated first, one concrete next action second, no raw Supabase/HTTP error text ever shown to the user |
| Destructive confirmation | not applicable — no destructive actions exist in Phase 1 scope (sign-out is not treated as destructive: no confirmation dialog required) |
