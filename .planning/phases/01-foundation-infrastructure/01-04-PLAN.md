<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → Supabase PostgREST | A third-party CI runner holds and transmits the Supabase anon key on every run |
| workflow logs → anyone with repo read access | Anything printed by a step is visible to every repo collaborator and, on a public repo, to the world |
| default-branch workflow file → scheduled execution | Any change to this file changes what runs unattended on a cron |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-15 | Information Disclosure | Workflow logs | mitigate | Credentials referenced only via `secrets.SUPABASE_URL` / `secrets.SUPABASE_ANON_KEY` so GitHub masks them; the step echoes only the numeric HTTP status, never the URL, key, or full curl command. Grep gates in Task 1 fail the task if a URL or JWT-shaped string is inlined |
| T-01-16 | Denial of Service (self-inflicted) | Supabase project pausing | mitigate | Daily cron issues a genuine PostgREST select (not a health check) against `profiles`, per Pitfall 4; wide margin against the 7-day window |
| T-01-17 | Repudiation / silent failure | Green-but-useless ping | mitigate | Explicit `%{http_code}` comparison against 200 with `exit 1` on mismatch, and no `continue-on-error` — a 404/401 turns the run red instead of masquerading as success |
| T-01-18 | Denial of Service | GitHub auto-disabling the schedule after 60 days of repo inactivity | accept | Documented in `docs/keep-alive.md` and in the workflow header; not solvable within GitHub Actions alone for a single-user side project. Accepted with a monitoring instruction (check Actions history if the project ever pauses) rather than pretended away |
| T-01-19 | Elevation of Privilege | Key scope used by the runner | mitigate | The workflow uses the anon key only — never `service_role`, which would let a compromised runner bypass RLS entirely. RLS from plan 01-02 means the anon request legitimately returns an empty array |
| T-01-SC | Tampering | Workflow supply chain | mitigate | The job uses no third-party marketplace actions at all — only `runs-on: ubuntu-latest` and inline `curl` — so there is no action pinning/compromise surface |
</threat_model>
